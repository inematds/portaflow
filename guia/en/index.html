What it is

A B2B sales machine project, documented before a line of code was written

PortaFlow sells white interior doors to stores and resellers. Today, this repository contains the phase that determines the success of everything else: the business diagnosis, the research that validates each technical choice against primary sources, and the 8-phase execution plan ready for an agent to implement. The code comes later—and it will be guided.

🚪 Price never comes from AI

The model extracts the data and describes the result. A deterministic engine connected to the real catalog does the calculation, with a versioned quote, unique ID, and expiration date—because under the CDC, a binding offer creates an obligation.

🚪 Evidence-based decisions, not guesswork

Seven architecture decisions backed by official documentation from Meta, Anthropic, Google, and Asaas, plus real production cases—including incidents others have already paid to learn from.

🚪 Multi-tenant from the first line

The architecture is built with separation by client and a swappable channel adapter. It starts as a custom system for one operation and can become SaaS for multiple stores without a rewrite.

How it works

From ad to paid order

The funnel outlined in the documents, with the points where the system is intentionally strict: the lead source is captured in the first message (it can't be recovered later), and every amount in reais goes through the quote engine before reaching the customer.

Ad / Search→ WhatsApp→ AI qualifies→ Quote engine→ Proposal→ Pix (deposit)→ Order
1

Lead generation

Google Search and click-to-WhatsApp ads. The campaign is optimized for the event of qualified lead using proxy value—not sales, which at a high ticket price don’t provide enough volume to train the algorithm.

2

Qualification

The AI identifies the profile (store, reseller, builder), city, door mix, dimensions, and timeline—in just a few exchanges, because starting in October 2026, every message has a cost on the official API.

3

Quote

Items, profile, volume, and ZIP code go into a pure function covered by tests; a quote comes out with an ID, expiration date, and the version of the price list used. Items outside the catalog don't get a number—not even a range.

4

Closing

A Pix payment link for the deposit and a second charge for the balance, both tied to the quote by an external reference—that's what links the confirmed payment back to the ad that generated the lead.

Prerequisites

What needs to be in place before coding

Phases 0 and 1 of the plan can be completed with what's already here. The remaining phases depend on data and accounts provided by the operation's owner—the repository includes the complete checklist in doc/lista_dados_necessarios.md.

Actual catalog

Export from the catalog system with products, dimensions, finishes, kit composition, and volume-based pricing. This unlocks the quote engine (phase 2).

# any format works
doc/catalogo_exemplo.csv

Dedicated number

One SIM card just for the bot—never the company’s main number. The channel starts with Evolution API and migrates to Meta’s official API when volume justifies it.

# brings up the channel + database + queue
docker compose up -d

Service accounts

A Telegram bot for internal operations, an account with a payment gateway to generate Pix charges via API, and the language model key.

# secrets stay outside the repo
cp .env.example .env
User guide · step by step

How to use this repository

The repository is designed to be run phase by phase by a coding agent (Claude Sonnet or Opus), with human review between phases. This is the path from zero to MVP.

1

Clone the project

All decision materials are version controlled: vision documents, research validation, and the master plan.

git clone git@github.com:inematds/portaflow.git
cd portaflow
2

Read in the right order

Start with the business diagnosis, move on to research validation (where the decisions are justified with sources), and finish with the execution plan.

# 1. the business and intended funnel
doc/diagnostico_vendas_portas_internas_brancas.md
doc/maquina_captacao_portas_visao_inicial.md
doc/visao_geral_maquina_vendas_portas.md

# 2. the 7 decisions backed by primary sources
doc/validacao_pesquisa.md

# 3. the master plan in 8 phases
PLANO.md
3

Complete the data checklist

The operations owner provides what only they know: catalog, volume-based price list, AI discount authority, service area, and lead times. Without items A to C, phase 2 is intentionally blocked.

$EDITOR doc/lista_dados_necessarios.md  # check off items as you deliver them
4

Start a session with the agent pointed at the plan

O PLANO.md is self-contained: it includes architecture, data model, contracts between modules, global constraints, and acceptance criteria for each phase.

claude   # in the project folder
# then ask: "read PLANO.md and execute Phase 0"
5

Execute one phase at a time, with a test closing the loop

Each phase becomes a detailed plan in doc/planos/ before it becomes code, it is implemented in a test-first cycle and only considered ready when the suite is green.

pytest -q          # green before anything is called "done"
git commit -m "feat: ..."
6

Validate the MVP in real conversations

The MVP's definition of done, at the end of phase 4: a real lead comes in through WhatsApp, is qualified, receives an accurate quote calculated from the catalog, pays the deposit via Pix—and the owner tracks everything through Telegram.

# in the operations bot
/resumo       # daily funnel: leads, qualified leads, quotes, sales
/assumir 42   # a human takes over the conversation; the bot pauses

Roadmap

The plan's 8 phases

Execution order with explicit dependencies. Phases 0 and 1 don't depend on the catalog and can start immediately.

Phase 0
FoundationRepository, containers, database, migrations, configuration, and test suite running.
Phase 1
Channel and operationsWhatsApp via a channel adapter, webhook with deduplication and message grouping, lead source tracking, and a Telegram bot with operational commands.
Phase 2
Catalog and quoteImport of the real catalog and the deterministic pricing engine, covered by reference tests validated by the operations owner.
Phase 3
Sales agentData extraction with range validation, lookup tools, safeguards against invented values, and automated evaluation of simulated conversations.
Phase 4
Closing and paymentPix payments for the deposit and balance, confirmation via an idempotent webhook, and order recording. MVP complete.
Phase 5
Follow-up and CRMA follow-up cadence that stops when the lead replies, classification of loss reasons, and funnel metrics through to margin.
Phase 6
Lead generation and attributionLanding page with tracking code, conversion reporting to Meta and Google, and campaign optimization for qualified leads.
Phase 7
Official APIMigration of the channel to Meta's official platform when volume, revenue, or a sign of number restrictions triggers the threshold.
